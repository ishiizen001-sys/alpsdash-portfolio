# AlpsDash Portfolio

複数拠点の販売データを、単なる集計ではなく**現場の意思決定につなげるために設計した業務ダッシュボードのポートフォリオ版**です。

> このリポジトリは転職・ポートフォリオ用途の再構成版です。実在する企業・店舗・商品・売上・顧客・従業員等のデータは含みません。すべて架空データです。

## Problem

複数拠点を運営する現場では、売上データが存在していても、次の問題が起きます。

- 店舗ごとに数字を見るタイミングや粒度が異なる
- 売上だけを見ても、客数と客単価のどちらが要因なのか分からない
- 数値確認と改善行動が別作業になっている
- データ欠損やマスタ不一致により、分析結果自体の信頼性が分からない

そこで、**データ取得 → KPI化 → 比較 → 異常検知 → 改善ポイント提示**までを一続きの意思決定フローとして設計しました。

## Design Principles

### 1. 売上を分解して見る

売上だけではなく、`売上 = 客数 × 客単価` として分解し、どこに変化が起きているかを判断できるようにしています。

### 2. 「見る画面」ではなく「判断する画面」

KPIの羅列ではなく、目標差・前期間差・店舗間差から、次に確認すべきポイントを明示します。

### 3. データ品質もKPIの一部として扱う

マスタ未一致、欠損、異常値などを可視化し、分析結果をどこまで信用できるか判断できるようにします。

## Run locally

簡易HTTPサーバーで起動してください。

```bash
python -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

## What this project demonstrates

このプロジェクトで見せたいのはダッシュボードの見た目そのものではなく、**曖昧な現場課題を、データ構造・判断基準・UIへ変換するプロセス**です。

技術は目的ではなく、現場がより早く正しい判断を行うための実装手段として選択しています。
